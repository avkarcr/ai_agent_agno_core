# Agno Core — локальная платформа мониторинга и ИИ-агентов

Минимальное **общее ядро** для будущих проектов: мониторинг новостей об акциях, инвестиционных показателей, погоды и событий в путешествиях, изменений в документации или нормативных актах.

Система проверяет заданные источники по расписанию, **детерминированно обнаруживает новые события или изменения значений**, сохраняет историю в SQLite и при желании обращается к **Agno-агенту**, который формулирует краткий комментарий. Уведомления можно отправлять в Telegram.

> **Статус: MVP / v0.1.0.** Это демонстрационная основа, а не торговый бот, система безопасности или готовый RAG-поиск. В первой версии нет авторизации, шифрования SQLite, повторной доставки неотправленных сообщений, сложного UI-редактора источников и гарантий непрерывного мониторинга.

## 1. Что уже умеет

- Поддерживает несколько независимых источников: **RSS/Atom** (новые записи) и **JSON HTTP API** (изменения скалярного значения).
- Запускает проверку вручную кнопкой или **автоматически через APScheduler**.
- Не присылает уведомления при первой проверке: она запоминает начальное состояние.
- Фильтрует повторные записи RSS, запоминает состояние источников между перезапусками.
- Записывает события, ошибки и время проверки в **локальную SQLite**.
- Позволяет включить **Agno** для анализа *только новых событий* (по умолчанию выключен, чтобы экономить ресурсы).
- Предлагает простую веб-страницу, REST API и вопрос к Agno-агенту о последних событиях.
- Может работать с **локальной Ollama** или через **OpenAI API**.
- Может отправлять события в Telegram, если заданы токен и chat_id.

### Что происходит при проверке

```text
RSS / JSON API
     │
     ▼
Сбор данных (HTTPX + feedparser)
     │
     ▼
Сравнение с сохранённым состоянием (обычный Python)
     │
     ├─ Нет изменений → только обновление статуса
     │
     └─ Есть изменения
           ├─ Сохранение события в SQLite
           ├─ [опция] Agno + LLM: краткий анализ
           └─ [опция] Telegram: уведомление
```

**Почему так:** LLM не должна определять, изменился ли номер рейса или показатель. Это точные сравнения. Агент нужен для интерпретации события и ответа на вопросы. Важно: ссылки на источники сохраняются, но само получение и достоверность данных зависят от внешних API.

## 2. Требования

- Ubuntu 24.04 / другой Linux (Windows/macOS также возможны при адаптации команд).
- **Python 3.11+**, рекомендуется 3.12.
- Интернет **для получения RSS/JSON данных**, даже если сама модель локальная.
- Для локального Agno-аналитика — установленная Ollama и загруженная модель.
- **На ноутбуке 4 CPU / 16 ГБ RAM / 250 ГБ SSD** приложение и SQLite запускаются без отдельного сервера БД. Локальная LLM на CPU работает, но ответ может занять заметное время.

Docker, Redis, PostgreSQL и Node.js **не требуются**.

## 3. Быстрый старт на Ubuntu

### Шаг 1. Получить проект

```bash
git clone https://github.com/avkarcr/ai_agent_agno_core.git
cd ai_agent_agno_core
```

### Шаг 2. Установить Python-зависимости

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip
python3 --version
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

Для тестов:

```bash
python -m pip install -e '.[dev]'
pytest -q
```

Команда `source .venv/bin/activate` нужна в каждом **новом** терминале (или используйте `.venv/bin/python` напрямую).

### Шаг 3. Создать локальные настройки

```bash
cp .env.example .env
cp watchers.example.json watchers.json
```

Два файла — **личная конфигурация**, их не нужно коммитить в Git. Отредактируйте `.env` и `watchers.json` любым редактором. Важно: после изменения `watchers.json` **перезапустите приложение**, чтобы загрузить новые источники.

На этом этапе **Ollama и Telegram ещё не обязательны**: сбор событий запускается без LLM.

### Шаг 4. Запустить API и веб-страницу

```bash
export AGNO_TELEMETRY=false
python -m uvicorn agno_core.api:app --host 127.0.0.1 --port 8000
```

Откройте:
- **Веб-интерфейс:** <http://127.0.0.1:8000/>
- **Интерактивная документация API:** <http://127.0.0.1:8000/docs>
- **Проверка работоспособности:** <http://127.0.0.1:8000/health>

Нажмите **«Проверить сейчас»**. Первая проверка только создаёт базовое состояние. Следующие проверки будут добавлять события при появлении новостей или изменении значения не меньше настроенного порога.

Остановить приложение: **Ctrl+C**. Автоматический опрос происходит по интервалу `CORE_POLL_MINUTES`, но **не сразу при старте**: для немедленного опроса используйте кнопку.

## 4. Как пользоваться веб-интерфейсом

В нём три части:

1. **Источники:** идентификатор, название, статус последней проверки и сообщение об ошибке (если есть).
2. **История событий:** новые RSS-записи и изменения числовых значений, время в UTC, оригинальные ссылки, результат уведомления.
3. **Спросить Agno:** чат-запрос к модели, которая умеет прочитать последние события из локальной истории.

Для примера: «Какие новые события зарегистрированы сегодня?». Эта функция требует **работающей LLM** и может быть ненадёжной на маленьких локальных моделях (вызовы инструментов).

Текущее окно чата не сохраняет многотуровую историю. Раздел «История событий» — постоянные записи базы, а не история переписки.

## 5. Работа с источниками (watchers.json)

Файл `watchers.json` — **JSON-массив объектов**. Добавьте один объект на каждый источник.

### Пример 1: RSS — новые новости

```json
{
  "id": "python-news",
  "title": "Python project news",
  "kind": "rss",
  "url": "https://www.python.org/blogs/rss/",
  "max_items": 20
}
```

При первом опросе запоминаются текущие новости. Потом каждое **новое** значение RSS `id` (или `link`) создаёт событие. Старые записи не должны уведомлять повторно.

### Пример 2: JSON API — температура Сеула

```json
{
  "id": "seoul-temperature",
  "title": "Seoul temperature (°C)",
  "kind": "json",
  "url": "https://api.open-meteo.com/v1/forecast?latitude=37.5665&longitude=126.9780&current=temperature_2m",
  "json_path": "current.temperature_2m",
  "min_delta": 2.0
}
```

`json_path` задаёт путь по вложенным ключам JSON через точки. В данном случае считывается `current.temperature_2m`. Если значение изменилось **на 2 °C или больше относительно последнего зафиксированного значения**, появится событие. Изменения меньше порога накапливаются.

Поля:

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `id` | Да | Уникальный идентификатор, латиница/цифры/`_`/`-` |
| `title` | Да | Подпись в интерфейсе и уведомлениях |
| `kind` | Да | `rss` или `json` |
| `url` | Да | Полный HTTP(S)-адрес источника |
| `json_path` | Для `json` | Путь до одного числа, строки или булева значения |
| `min_delta` | Нет | Порог изменения числа; по умолчанию 0 |
| `max_items` | Нет | Сколько записей RSS читать за один опрос; по умолчанию 20 |

**Ограничения v0.1:** нет API с OAuth/сложными заголовками, пагинации, входа на сайты, JavaScript-рендеринга и отдельных расписаний по источникам. Проверяйте ограничения частоты запросов и условия использования выбранных источников. Не сохраняйте токены внутри URL, если не хотите видеть их в логах или в истории.

## 6. Подключить Agno к локальной Ollama

По умолчанию сбор данных работает **без LLM**. Для кнопки «Спросить Agno» или автоматического анализа нужно установить Ollama.

### Установить Ollama

Официальная инструкция: <https://ollama.com/download/linux>. Для установки через официальный скрипт:

```bash
curl -fsSL https://ollama.com/install.sh | sh
sudo systemctl enable --now ollama
ollama --version
```

Перед выполнением сетевых установочных скриптов их можно предварительно скачать и проверить.

Загрузите сравнительно небольшую модель:

```bash
unset OLLAMA_API_KEY
ollama pull qwen2.5:3b
ollama list
ollama run qwen2.5:3b
```

Для выхода из интерактивной Ollama: `/bye`. Если нужна модель с более надёжными инструментами, можете экспериментировать с `qwen3:4b`, но на CPU она может оказаться медленнее.

В `.env`:

```dotenv
AGNO_TELEMETRY=false
CORE_MODEL_PROVIDER=ollama
CORE_OLLAMA_MODEL=qwen2.5:3b
CORE_OLLAMA_HOST=http://127.0.0.1:11434
CORE_ANALYZE_CHANGES=true
```

После изменения перезапустите API.

- `CORE_ANALYZE_CHANGES=false` (по умолчанию): наблюдение и запись событий **без обращений к LLM**. Кнопка «Спросить Agno» всё равно использует модель.
- `CORE_ANALYZE_CHANGES=true`: модель комментирует каждое **новое** событие.
- Для строго локальной Ollama убедитесь, что `OLLAMA_API_KEY` не установлен, `CORE_OLLAMA_HOST` указывает на локальный сервер и выбранная модель **не облачная** (без суффикса `-cloud`).

**Важно:** локальная модель означает локальный *анализ*. RSS, погода и Telegram по-прежнему требуют выхода в интернет. Источники API могут получать сведения о ваших запросах.

### Альтернатива: GPT через OpenAI

```bash
python -m pip install -e '.[openai]'
```

Добавьте в `.env`:

```dotenv
CORE_MODEL_PROVIDER=openai
CORE_OPENAI_MODEL=gpt-5-mini
OPENAI_API_KEY=YOUR_KEY_HERE
CORE_ANALYZE_CHANGES=true
```

Это платный API, и содержимое переданного событию/вопросу контекста отправляется поставщику модели. **Подписка ChatGPT не включает API-кредиты.**

## 7. Telegram-уведомления

1. В Telegram обратитесь к официальному **@BotFather**, создайте нового бота и получите токен.
2. Напишите созданному боту `/start`.
3. Узнайте идентификатор диалога: `https://api.telegram.org/bot<ТОКЕН>/getUpdates` (в ответе найдите `message.chat.id`; ссылка **с токеном секретная**, не публикуйте её).
4. В `.env` задайте:

```dotenv
CORE_TELEGRAM_BOT_TOKEN=123456:YOUR_SECRET_TOKEN
CORE_TELEGRAM_CHAT_ID=123456789
```

5. Перезапустите сервер. При **новом** событии придёт сообщение. Для проверки используйте новый RSS-пункт или контролируемое изменение значения тестового JSON.

Если токен или chat_id не заданы — событие остаётся в SQLite со статусом `local`. При неудачной отправке ставится `failed`; **автоматической повторной доставки пока нет**. Учитывайте конфиденциальность: содержимое уведомлений отправляется Telegram.

## 8. Настройки .env

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `AGNO_TELEMETRY` | `false` из шаблона | Выключить телеметрию Agno |
| `CORE_DB_PATH` | `.local/core.sqlite3` | Путь к SQLite |
| `CORE_WATCHES_FILE` | `watchers.json` | Список источников |

| `CORE_ANALYZE_CHANGES` | `false` | Автоматический вызов LLM для новых событий |
| `CORE_MODEL_PROVIDER` | `ollama` | `ollama` или `openai` |
| `CORE_OLLAMA_MODEL` | `qwen2.5:3b` | Имя загруженной Ollama-модели |

| `CORE_OPENAI_MODEL` | `gpt-5-mini` | OpenAI-модель |
| `OPENAI_API_KEY` | — | Ключ внешнего API |

| `CORE_TELEGRAM_CHAT_ID` | — | Получатель уведомлений |

Пути считаются относительно текущего рабочего каталога. Поэтому запускайте команды из корня проекта.

## 9. REST API: пользоваться без веб-интерфейса

После запуска (`127.0.0.1:8000`):

```bash
# Состояние приложения
curl -s http://127.0.0.1:8000/health

# Список источников и последние ошибки
curl -s http://127.0.0.1:8000/api/watches

# Проверить источники сейчас
curl -s -X POST http://127.0.0.1:8000/api/run

# Последние 10 событий
curl -s 'http://127.0.0.1:8000/api/events?limit=10'

# Спросить агента (нужна работающая модель)
curl -s -X POST http://127.0.0.1:8000/api/ask \
  -H 'Content-Type: application/json' \
  -d '{"question":"Кратко перечисли изменения и дай ссылки на источники"}'
```

Полная интерактивная спецификация — `/docs`. API работает в локальном режиме **без ключей и авторизации**, поэтому **не используйте** `--host 0.0.0.0`, не делайте прямой проброс порта из интернета и не открывайте публичный доступ без защищённого reverse proxy и аутентификации.

## 10. Как запустить постоянно (systemd user)

Сначала убедитесь, что ручной запуск работает. Для постоянной работы на включённом ноутбуке используйте `systemd --user`.

Создайте файл `~/.config/systemd/user/agno-core.service`:

```ini
[Unit]
Description=Agno Core local monitoring
After=network-online.target

[Service]
Type=simple
WorkingDirectory=%h/projects/ai_agent_agno_core
ExecStart=%h/projects/ai_agent_agno_core/.venv/bin/python -m uvicorn agno_core.api:app --host 127.0.0.1 --port 8000
Restart=on-failure
RestartSec=10

[Install]
WantedBy=default.target
```

**Обязательно замените** `%h/projects/ai_agent_agno_core` на реальное расположение клонированного проекта под домашним каталогом.

```bash
mkdir -p ~/.config/systemd/user
# сохраните показанный unit в ~/.config/systemd/user/agno-core.service
systemctl --user daemon-reload
systemctl --user enable --now agno-core
systemctl --user status agno-core
journalctl --user -u agno-core -f
```

Чтобы остановить: `systemctl --user stop agno-core`. Чтобы отключить автозапуск: `systemctl --user disable agno-core`.

Ноутбук **не проверяет события, пока выключен или находится в состоянии сна**. Для круглосуточного мониторинга перенесите лёгкий сборщик на VPS; лучше не переносить туда вашу полную инвестиционную базу.

> Не запускайте одновременно несколько копий сервера с планировщиком: каждая будет выполнять проверки. Этот MVP рассчитан на **один процесс Uvicorn, один worker**.

## 11. Где хранятся данные, сброс состояния и резервное копирование

По умолчанию: `.local/core.sqlite3`.

В таблице `states` лежит предыдущая выборка/базовое значение и ошибки; в `events` — история обнаруженных изменений и статусы отправки. **Файл не шифруется**; используйте шифрование диска/каталога и ограничьте доступ к профилю пользователя. Не коммитьте базу в Git.

Чтобы полностью сбросить историю и базовые значения, **остановите сервис**, сделайте резервную копию и удалите SQLite-файл:

```bash
cp .local/core.sqlite3 core-backup.sqlite3
rm .local/core.sqlite3
```

При следующем запуске база появится снова, а первая проверка заново инициализирует базовое состояние. Для резервного копирования во время работы корректнее использовать SQLite backup API, а не просто копировать открытый файл.

## 12. Проверки и диагностика

```bash
source .venv/bin/activate
python -m compileall -q agno_core tests
python -m pip install -e '.[dev]'
pytest -q
```

**Приложение не стартует: `Missing watchers.json`** — выполните `cp watchers.example.json watchers.json`.

**Ошибка доступа к Ollama / модель не найдена** — проверьте `systemctl status ollama`, `ollama list`, `curl http://127.0.0.1:11434/api/tags`, имя модели в `.env`.

**При первой проверке «0 событий»** — это нормально: система запоминает базовое состояние. Дождитесь новых публикаций / существенного изменения значения.

**Ошибка 429/403/timeout у источника** — API может ограничивать запросы или сеть может их блокировать. Сократите частоту проверок и проверьте URL обычным `curl`. Ошибки видны в разделе «Источники».

**Не приходят сообщения в Telegram** — проверьте токен, chat_id, что бот получил `/start`, сетевую доступность Telegram API и статус `delivery` в истории.

**Агент ничего не находит** — на первой проверке новых событий нет. Кроме того, небольшая локальная модель может не вызвать инструмент `recent_events`; попробуйте более способную модель или смотрите сырые события через `/api/events`.

## 14. Как расширять под свои проекты

**Инвестиции.** Добавить коллекторы MOEX ISS, Банка России, корпоративных RSS и раскрытия информации. Сбор числовых показателей и расчёт индикаторов — детерминированный Python; агенты интерпретируют уже проверенные данные. Для инвестиций создать отдельные таблицы и безопасный интерфейс, а не смешивать сделки с мониторинговыми событиями.

**Путешествия.** Создать источники статусов рейсов/поездов, погоды и официальных предупреждений. Рекомендации по перестановке маршрута делать только с учётом фиксированных бронирований, временных окон и вашей явной команды. **Не** изменять билеты автоматически.

**Информационная безопасность / нормативные документы.** Собственные collectors сравнивают измерения DNS, сертификаты, версии документов; агент объясняет влияние изменений с исходными ссылками.

Пока для каждого источника используется единый интервал и простая логика сравнения. Следующим шагом стоит добавить **плагины-коллекторы**, нормализованную модель события, приоритеты, пороги уведомлений, локальную аутентификацию и надёжную очередь доставки.

## 15. Безопасность и ограничения

- Только **localhost**: в MVP отсутствуют логин/пароль/авторизация.
- **SQLite не зашифрована** и сохраняет URL и детали событий.
- Внешний LLM может получать заголовки, описания и URL событий; используйте локальную модель для закрытых материалов.
- Текст RSS/JSON — потенциально недоверенный; система не исполняет его как код, а агенту запрещено считать текст инструкцией.
- **Никаких торговых операций, изменения бронирований или действий от имени пользователя**.
- При отказе Telegram событие остаётся в истории, но **не отправляется повторно автоматически**.
- Состояние источника сохраняется до отправки, чтобы не создавать дублей при сбое.
- Нет SLA, нет мониторинга самого мониторинга, нет distributed lock и защиты от параллельных процессов.
- Это **не RAG**: PDF, embeddings и векторную БД можно добавить отдельным модулем позже.
